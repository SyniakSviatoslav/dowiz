## 3. Architecture map (bebop.bp)

bebop.bp is a **single-pass, text-driven emitter**: no token buffer, no AST, no IR. The cursor is `pos[0]` over the source string `s` (source length carried in `pos[1]` since the slen fix, bebop.bp:103); symbols live in `stab`; all per-function state lives in one 4096-cell `fntab` (zeros(4096) at bebop.bp:2798, 3544, 3571, 3940, 4105).

Order in `emit_binop_regs` (2022-2028): madd -> shl -> mulc -> addshift -> plain.

**Invariants that protect the folds**

- `fntab[3660]` = last label/barrier position (set by emit_cond 2469/2474, emit_while_stmt 3088/3131, pop rd=0 1631, cond_branch_word 2444). Every retraction checks it (`nolab`/`lab1`), so no jump target is ever inside a retracted pair — the one rule that makes stream-contiguous rewriting sound without a CFG.
- Fold model `fntab[3655..3659]` (depth, top const, chunk lengths) cleared by `fold_clear` on every push/pop/branch; depth model `fntab[3700]` + slot tags 3701+ (bookkeeping only, L16: push/pop emit exactly their canonical words, bebop.bp:1591-1596 comment).
- L16/L1: every word is python-derived and objdump-checked; the constants in the comments of shl_try/mulc_try/cmp_try carry the as+objdump samples.
- Post-hoc gates: `word_budget.txt` (a construct that GREW needs a line, construct_parity.sh:34 `WORD_BUDGET_MISSING`), `census.txt` + `census_allow.txt` (bcond/cbz/tbz never increase without a line; invariants.sh (ii)), `check_abi.py` (register zones, fntab zone map, footer/entry identity), 44 frozen construct word streams + values, `census_allow` for the compiler, fixpoint gen3==gen4, `typecheck` census (vii), `gen_selfsrc` identity (v).

## 4. Risks and gaps

### A. What the docs claim that the code/gates do not enforce

1. **"0 CRASH / DIVERGE" is not "0 unexplained traps."** fuzz.sh:60-61 folds `TRAP-80 + TRAP-81 + TRAP-82` into `TRAP-UNPREDICTED` = "bebop trapped, the oracle did not predict it" (fuzz.sh:11-12: "frame heap is not modelled by bpref"). fuzzd.sh:33 raises an ALERT **only** on `DIVERGE|CRASH|COMPILEFAIL`; TRAP-UNPREDICTED never alerts, and the fuzzd journal lines all say `VERDICT:confirmed` with 1-8 unpredicted traps each — **173 over 37,100 seeds (0.47 %)**. TRAP-82 is SIGSEGV/SIGBUS: an unpredicted SEGV is exactly what a wild-store miscompile looks like, and this classification cannot tell it from deep recursion. bench/fuzz/repros has only `TRAP-81-*` files (2) — the 82s are not kept.
2. **BPREF-TIMEOUT 190 (0.51 %)** = programs whose oracle result is unknown (40 s budget); they count neither as OK nor as a finding.
3. **T123 "every gate mutation-sensitive" is a one-time sweep**: tools/mutate_gate.sh is in neither tools/battery.sh nor tools/chain.sh (grep = 0). New goldens or oracle edits can regress to self-frozen without notice; run_all.sh's `self-frozen=0` checks oracle==golden, not sensitivity.
4. **T48 "checked types at zero runtime cost" is DONE only as a python census** (invariants.sh:44-48, tools/typecheck.py over bpref's AST). The compiler itself never reads a type (bebop.bp parse_params 222). LANGUAGE.md:9 still says "T48 will check them" while TASKS.md says DONE, and ROADMAP step 4 reopens it as "T48 rest". Three documents, three states.
5. **The honesty floor is python.** 101 oracles, bpref.py (the only semantic oracle for the compiler), typecheck.py, census.py, check_abi.py, gen.py, ladder.py, fuzz_batch.py — 133 tracked .py files. "No C anywhere in the toolchain" is true of the runtime path only; python 3.14.4 is unpinned and unmanifested. A shared misreading between bpref.py and bebop.bp becomes "correct by agreement" (T125 precedent: `&&`/`||` without short-circuit was made to match bebop.bin rather than the other way round).
6. **The entry stub is outside the language and outside the fixpoint.** SESSION-HANDOFF: "edit brk/stub.S in a scratchpad, `as` + `objcopy`, regenerate the `st[i] =` lines with python, update the 131/42/132 constants in cli_compile". The stub's correctness rests on check_abi finding the `b .` placeholder and on the four runtime diag probes; nothing rebuilds it from source in a gate. GNU binutils (C) is a hidden dependency of every trap-message change.
7. **TASKS.md is stale relative to ROADMAP.md** (T90 PARTIAL vs CLOSED; T77 OPEN vs ladder.py DONE; `T101-T108 OPEN` with 7/8 DONE). The "generated ledger" is regenerated from HISTORY.md headers by hand (tools/roadmap_check.sh); no hook runs it.
8. **LANGUAGE.md carries two contradictory "Frame heap" paragraphs** (lines ~104-112: "released at the back-edge and at loop exit (T43)" vs "die at return … reset per iteration when the compiler can prove no pointer escapes") — the second is the pre-T43 text left in place.
9. **emit_var's unbound-symbol path is mislabelled**: bebop.bp:2063-2065 says "keeps the legacy xzr load (unresolved calls read xzr)" but the word 2852127712 is `mov x0,x0` (ORR x0,xzr,x0), a no-op — an unbound read returns whatever x0 holds. LANGUAGE.md says UNDEFINED, which is the truth; the comment is not.
10. **In-progress `cmp_try` (bebop.bp:2184-2207)**: `both` retracts P_a=`mov x0,xR` and reads xR in the cmp. If P_b is `mov x1,x0` (rs=0) — which pop2 produces from the `mov x0,x0` no-op above — the emitted `cmp xR,x0` reads a stale x0. Only reachable from an undefined program, but a `* (if rs != 0 …)` term in `both` is one cheap guard. Also: `cmp_try` adds ~10 `if`s -> the census will need an ALLOW line; the 16 re-frozen bins in the tree show it fires on c04/c05/c07/c09 etc.
11. **Fuzz coverage is per binary but counted cumulatively.** 28,500 of 37,100 fuzzd seeds ran on d785e062; the next promotion resets the promoted binary's fuzz history to 0 while TG-DONE 8's "10^5" keeps accruing. (The 3,100 + 5,000 pre-fuzzd seeds in ROADMAP 1a ran on older binaries.)
12. **Golden compiler is stale.** bench/golden has one binary, `bebop-8ec62df.bin` — before T96, T99 (`return`/`break`), T47 (`use`), T80 (cas), T130, T118b. It is doubtful it can compile HEAD's bebop.bp (which begins with `use`, uses `return`/`break`, `clz`, `crc32x`). L13 recovery therefore depends on git history of bebop.bin, not on the golden.

## VERDICT

- The thesis is real and measured: a 194-fn, 76k-word self-hosting compiler at a byte-exact fixpoint, 99 oracle-backed gates + 52 constructs, a store with G1-G8 numbers, speed 1.6-3.4x Rust (target <= 2.0x, 2 rows unmet). The critical path that remains is small: P3 (S, in the tree), P2 (M), three background measurements — after that every OPEN item is a parked decision or a separate project; the 37-OPEN count overstates remaining core work by ~25 items.
- The biggest honesty gap is in the fuzz story: 0.47 % unpredicted traps (incl. SIGSEGV) never alert, 0.51 % oracle timeouts are uncounted, coverage is 37k/100k cumulative and 28.5k on the promoted binary, and mutation sensitivity is a one-time sweep, not a battery lane.
- Single points of failure: a committed 1,480 B loader with no rebuild gate, a stale golden compiler that predates `use`/`return`/`cas`, a python-only oracle floor, and one proot box with a 30-process cap.
- Housekeeping is drifting: TASKS.md disagrees with ROADMAP.md on three tasks, LANGUAGE.md contradicts itself and the ledger on T48/frame heap, and the working tree mixes a codegen diff with doc edits mid-chain.
- Nothing measured today tracks memory, energy, size trend or tail latency beyond K1-K4 p95; those are the numbers the store claim (D11-I) will be judged on next.
