Generated by static analysis (`grep`/`search` over the repository). No `.lean`,
`.v`, `.thy`, or `.idr` files exist anywhere in the tree — formal verification is

> **Bottom line:** formal verification coverage is near zero. Exactly **3

> harness that is **not wired into the compilation pipeline**; `verifier_prove` is a
> placeholder that flags nothing, and `qtt_prove_induction` is a stub that accepts
> any input.

## 3. (b) Formally proved theorems

**3 theorems are machine-checked** (via `refl` → definitional-equality/conversion
check in the QTT proof kernel). All live in `samples/theorem-sample.bp`:

| Theorem | Proposition | Proof | Status |
|---|---|---|---|
| `plus_one` | `(λx:i64. x+1)(4) = 5` | `refl` | ✅ proven (β+δ) |
| `arith` | `1 + 2 * 3 = 7` | `refl` | ✅ proven (closed arithmetic fold) |
| `beta_nested` | `(λx:i64.x)((λy:i64.y)(7)) = 7` | `refl` | ✅ proven (nested β) |
| `bad` (in `theorem-false.bp`) | `1 + 1 = 3` | `refl` | ❌ must be **rejected** (build exits 1) |

Proving path: `theorem_prove()` (`theorem.c`) → `qtt_prove_refl()` (`qtt.c`) →
`qtt_prove()` conversion check. This is the **only** formal-verification path that
is wired into the compiler (`bebop check`, `main.c:827`).

Kernel-level proof self-tests (registered as `qtt_proof`, `qtt_nat` in `startup.c`):
- `qtt_proof_test`: 4 checks — `refl 5 : 5=5`, `refl ((λx.x+1) 4) : …=5`, **reject**
  `refl 5 : 5=6`, `subst H H : 2=2`.
- `qtt_nat_test`: additionally proves `refl (nat_rec …) : double 2 = S^4 Z` and an
  induction case.

**Limitations (important):**
- `qtt_prove_induction()` (`qtt.c:2676`) is a **stub** — it accepts *any* input and
  prints `"induction: accepted (structural proof)"` without checking. So "induction"
  proofs are not actually verified.
- All 3 proven theorems are trivial identities on closed terms; there are **no
  non-trivial (e.g. inductive/universal) proved theorems** in the tree.
- `selfhost/proof.bp` (4 functions: `refl`, `sym`, `trans`, `subst_basic`) is *not*
  a set of proved theorems — they are plain `i64` witness functions that return
  `0`/`1` at runtime. Similarly `qtt_kernel.bp` (11 fns: `ty_eq`, `eval`, `subst`,
  `norm`, `conv`, `is_num`, `ty_unify`, `ty_if`, `ty_binop`, `test`, `self_check`)
  and `qtt_types.bp` (5 fns: `is_num`, `ty_unify`, `ty_if`, `ty_binop`, `ty_arr`)
  are runtime "kernel" implementations, **not formally verified**.

## 4. (c) Auto-verifier coverage

The auto-verifier (`verify`/`verifier`/`termination`/`contract`) is exercised
**only by its own self-test functions**, never applied to real modules:

- `verifier_prove` is called **only** inside `verifier.c` (self-test). `verify_bounded`
  only inside `verify.c` (+ a bench fuzz harness `bench/r6/r6_fuzz.c`).
  `bp_contract_check` only inside `contract.c`. None are reachable from
  `cmd_check`/`cmd_compile` — **the auto-verifier does not run during compilation.**
- Only `theorem_prove` is wired into the real pipeline (`main.c:827`).
- `verifier_prove` is a **no-op placeholder**: it increments a `checks` counter for
  each `[` array access it sees and reports `"verifier: N checks, 0 violations"`,
  always returning 0 (no property is actually verified).
- Termination checker `qtt_termination_check()` (`termination.c`) walks a `Term`
  structurally and enforces `nat_rec`/`nat_ind` targets are `Nat` terms; it is
  exercised on **2 synthetic terms** in `qtt_termination_test`.

Self-test module registry (`startup.c` `MODS[]`): **79** modules total, of which
**10** are verification-related (`qtt`, `qtt_check`, `qtt_eval`, `qtt_conv`,
`qtt_proof`, `qtt_nat`, `termination`, `verify`, `verifier`, `contract`). These are
runtime assertion tests of the machinery, not proofs about library code.

**Net: 0 modules/kernels in `selfhost/` (or `native/src/`) are actually verified by
the auto-verifier.** The auto-verifier verifies nothing but its own hand-written
test inputs.

## 6. Honest caveats

1. **Contract syntax is not implemented.** There is no parser/surface that attaches
   `requires`/`ensures` to a Bebop `fn`. The contract checker only understands a
   single-letter-variable boolean grammar (`a && b`, `!a -> b`, …) — far too weak for
   real preconditions.
2. **Induction is not verified.** `qtt_prove_induction` is an unconditional stub.
3. **The auto-verifier is inert.** `verifier_prove` flags nothing; the verifier is
   never invoked by `compile`/`check`.
4. **Proven theorems are toy examples.** All three are definitional-equalities on
   closed i64 terms; none exercises dependent types, universes, effects, or the
   self-host compiler itself.
5. **Function counts are approximate.** The C count (≈755) is a regex heuristic; the
   `.bp` count (675) counts `fn` declarations by keyword. Treat both as ±a few
   percent.
