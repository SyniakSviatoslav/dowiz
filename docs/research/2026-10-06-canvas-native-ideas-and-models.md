# Canvas-native ідеї та моделі з Hugging Face для dowiz на одному `<canvas>` — дослідження R-CANVAS2

Lane R-CANVAS2, 2026-10-06, model Fable (session 264e2624). Дослідницький лейн: код продукту не змінено; прототипи лише у scratchpad `canvas2-lab/` (`tm/` — бенч «машини часу» на справжніх `dowiz-hub`/`bebop-store`, `ort/` — виміри ONNX-моделей під wasm, `hf_sizes.py` — розміри з HF API). Кожне число — **FRESH** (команда, rc, файл виводу), **RECORDED** (джерело + умови) або **ESTIMATE** (сказано прямо). Продовження `docs/research/2026-10-06-canvas-rust-webgl-ui.md` (R-CANVAS) і `2026-10-06-s7-sheaf-engine-arxiv-and-experiments.md` (R-S7); контекст рішень — Wave CV у `docs/design/ROADMAP-2026-09-22.md`.

## 0. Десять рядків для оператора

1. **Чотири ідеї ззовні — три варті побудови, одна (мультикурсори) ні.** Але фактичне твердження першої («історія лежить двійковими дельтами завдяки W-OCHAIN») **хибне**: W-OCHAIN — це O(n) скан заголовків `EvLog` (`crates/dowiz-hub/src/read/history.rs`), а не дельти; дельти замовлень (`_d`, JSON) існують з D7 (`room/delta.rs`); KV-образи компактуються без історії; W-DELTA додає ланцюг дельт з компакцією — обмежену, не повну історію.
2. **«Машина часу» по замовленнях можлива й дешева (FRESH):** 30-денний гарячий лог (900 замовлень, 5 400 подій) — кадр слайдера **1,2 ms p50 / 3,2 ms max** із чекпоінтами кожні 64 події, 4,5 ms без них; відкриття логу 4,6 ms + 11 ms розбір і сортування. Умова: штампи часу вже є в payload замовлень (`created_at_ms`, `confirmed_ms`, `cooking_ms`, `ready_ms`, `picked_ms`, `delivered_ms`, `at`).
3. **Стоковий лог «машиною часу» не відмотати:** `stock/codec.rs` не пише час у жодну подію — лише порядок. Один новий атрибут (`at`) у кодеку й декодері (закони S7c) відкриває склад для слайдера; без нього — лише «n-та подія».
4. **Видима склейка пучка** — чиста UI-робота над відповіддю `glue()` (S0): прапори по ребрах, `radius_edges` (S7a), provisional-продажі, що проходять або відхиляються при rebase (E5: 20 % відхилених). Нічого нового на сервері; 3–5 лейн-днів після S2 і CV1.
5. **Теплокарти** мають законні дані: кухонні квитки з часом по станах, стан столів (`FLOOR_STATES`), таблиця продажів (`analytics/cube.rs` — по днях; **години** потрібно додати: 24 цілих на страву на день). Заборонено: тепло поведінки гостя (no-tracking) і тепло «по офіціанту» без явної правки D0.
6. **Моделі з Hugging Face на телефоні (FRESH, 1 потік A78, wasm):** silero-VAD 2–22 ms; MiniLM-мультимовний q8 (118 MB!) 145 ms на 32 токени; MODNet (видалення фону, 6,6 MB, Apache-2.0) 3,75 s на фото 512²; Depth-Anything-V2-small (27 MB, Apache-2.0) 11,6 s; whisper-tiny енкодер 3,6 s на 30 s звуку; SlimSAM енкодер 14,9 s і 2,2 GB RSS. Рантайм onnxruntime-web: **11,2 MB wasm** (+21,9 MB для WebGPU-збірки) + 358 KB JS.
7. **Висновок по моделях: один раз при завантаженні фото в консолі власника — так; на телефоні гостя за кожним кадром — ні.** Фон і карта глибини рахуються раз (секунди в консолі), зберігаються як малі растрі поруч із фото, а вітрина лише малює (шейдер паралаксу/підсвітки — 0 ms моделі).
8. **Мова для голосового обліку: лишити Web Speech API** (уже в `lib/voice.js`, безкоштовно, `sq-AL`). whisper-tiny на телефоні — 3,6 s на 30 s лише енкодер, якість для албанської не виміряна; ліцензійно чисті великі моделі (MMS, NLLB) — **CC-BY-NC**, комерційно заборонені. Серверний варіант — Workers AI `@cf/openai/whisper` у межах 10 000 нейронів/день на весь акаунт.
9. **Найцінніші власні ідеї:** (a) детермінований реплей — баг-репорт = префікс подій (рушій без годинника й RNG усередині wasm); (b) рейка кухонних квитків зі старінням як кольором/теплом; (c) режим низької потужності (малювати лише за подією, dpr ÷ 2, Sea вимкнена) — без `getBattery`, якого вже не дозволяє no-tracking; (d) власна цілочисельна таблиця ембедингів словника венуї (~0,5 MB int8) замість 118 MB моделі для пошуку меню трьома мовами.
10. **Чого не будувати:** моделі в Worker-і (10 ms CPU), whisper/LLM на телефоні гостя, RMBG/NLLB/MMS (ліцензія), мультикурсори офіціант↔кухня, тепло по людях, haptics на iOS (немає API без DOM), WebGPU як базовий шлях.

## 2. Чотири ідеї ззовні — чесна оцінка

### 2.1 «Машина часу» — слайдер назад по дню

**Твердження «історія зберігається двійковими дельтами завдяки W-OCHAIN» — хибне** (§1). Що правда: лог замовлень append-only, кожен префікс — валідний стан, штампи часу в payload. Що можна відмотати і скільки це коштує — виміряно (`canvas2-lab/tm`, path-залежності на справжні `dowiz-hub`, `bebop-store`; збірка через slot.sh rc=0, 1 m 13 s; три запуски rc=0):

| Лог | Відкриття (`events_oldest_first`) | Розбір JSON + сортування за штампом | Кадр без чекпоінтів (fold з нуля) p50 / max | Кадр з чекпоінтами p50 / max | Чекпоінтів / байт (JSON-еквівалент) | Крок на одну подію |
|---|---|---|---|---|---|---|
| 900 замовлень / 5 400 подій / 685 KB payload (30 днів × 30 замовлень), K=64 | 4,62 ms | 10,96 ms | 4,53 / 7,36 ms | **1,17 / 3,20 ms** | 85 / 23,6 MB | 1,9 µs |
| те саме, K=256 | 5,22 ms | 12,54 ms | 5,03 / 8,22 ms | 1,29 / 4,25 ms | 22 / 6,1 MB | 2,0 µs |
| 300 замовлень / 1 800 подій / 227 KB, K=64 | 1,54 ms | 3,75 ms | 1,61 / 4,41 ms | **0,41 / 1,80 ms** | 29 / 2,7 MB | 4,7 µs |

Файли: `canvas2-lab/tm/tm-900-64.out`, `tm-900-256.out`, `tm-300-64.out` (A78, slot 1, один потік; `build_ck_ms` 879 ms для K=64 — одноразово при відкритті, 83 ms для K=256). Отже **кадр слайдера вкладається в бюджет CV7 (p99 ≤ 8 ms) навіть без чекпоінтів на 30-денному лозі**; з чекпоінтами K=256 — 1,3 ms і 6 MB пам'яті. Чекпоінти — у пам'яті wasm, нічого не пишеться на сервер.

Що **відмотується**: кожне замовлення (статус, позиції, стіл, гроші), отже кухонні колони, зайнятість столів з замовленнями, ETA-історія (`fulfilment.eta_ms` у дельтах). Що **не відмотується**: стан столу з бронюваннями (`state_of` рахує сервер — треба портувати правило в Rust або отримати знімки), склад (без часу), каталог/ціни (KV без історії; «що коштувала страва о 14:32» — лише з чека `X4`/S5), усе старше 30 днів (архіви — по днях).

Що гарантує canvas, чого DOM не дає: стан на час t — це той самий fold, що малює живу дошку; слайдер — лише інший `t`. У DOM кожен кадр = переклеювання сотень вузлів; тут — один `frame()` над готовим станом (R-CANVAS: 1,7 ms/кадр CPU).

Приватність: лог містить контакти гостей (`contact`) — слайдер лише на поверхнях персоналу з правом бачити замовлення; `Revealed`-подія (хто дивився контакти) лишається аудит-фактом і теж відтворювана.

**Вердикт:** будувати як **CV8c** після CV1; 3–5 лейн-днів; пропозиція додати `at` у стокові події (S7c-закони міграції) — окремий крихітний рядок **CV8c′** (1 день, у `dowiz-hub`, не canvas).

### 2.2 Видима склейка пучка

За S0/S1 (`glue()` повертає прапори по ребрах `hub∩kitchen∩waiter`, `radius_edges`, список provisional з вердиктом rebase; E1: 102 µs; E5: 3,6 % продажів provisional, з них 20 % відхилено) усе, що потрібно для анімації, вже є у відповіді ендпоінта `POST /do/glue` (S2). Сцена: контексти як вузли, ребра накриття з числом розбіжності (radius), хвіст планшета «летить» у лог хаба запис за записом (кілька сотень за день кухні — 20 записів у типовій склейці), provisional стають зеленими/червоними в момент rebase; відхилені — відкривають наявний flow «кухня вирішує». Дає персоналу відповідь на «чому мій продаж відхилено» і довіру до офлайн-режиму; дає нам візуальний тест S0 (кожен прапор E1 має свій кадр).

Коштує: 3–5 лейн-днів UI після S2 і CV1; 0 серверних змін; wasm +ESTIMATE 15–25 KB (сцена + анімації). Межа: гість цього не бачить і не має — склейка стосується даних венуї.

**Вердикт:** будувати як **CV8f**, залежить від S2 (ендпоінт) і CV1; поки S2 нема — макет на даних E1/E5 (синтетика) допустимий як демо для оператора.

### 2.3 Живі теплокарти

| Що гріти | Джерело даних | Законність | Вартість |
|---|---|---|---|
| Квитки кухні за віком/станом (станція, час у COOKING проти `prep_min` страви) | `created_at_ms`, `cooking_ms`, `ready_ms` у payload; стоп-лист | персонал; про замовлення, не про людей — ок | у CV1 (+1–2 дні) |
| Столи: зайнятість за годину/день тижня, тривалість сидіння | fold замовлень по `fulfilment.table` з гарячого логу (30 днів) | ок | 1–2 дні після CV8c |
| Страви «цієї години» (популярність) | гарячий лог за годиною; таблиця продажів по днях **без годин** — додати 24 цілих на страву на день у `cube.rs` | ок (операторське `popular` 10-03; факти замовлень, не поведінка) | 1 день у `cube.rs` + 1 день сцени |
| Тепло поведінки гостя на меню (де затримується палець) | лише на пристрої гостя (`taste-device.js`) | **показувати власнику заборонено** (no-tracking: нічого не залишає пристрій) | не будувати на сервері |
| Тепло «по офіціанту» | можливо з логу | потребує явної правки D0 + повідомлення персоналу + DPIA (рішення 10-03 про особисті KPI) | не в CV8; окреме рішення |

Чого DOM не дає: 24×7 клітинок × 165 страв або столи з градієнтом — на canvas це одна текстура/один прохід; у DOM — тисячі елементів. Ключовий нюанс для цілочисельного правила: тепло = цілі лічильники, колір — таблиця з 16 кроків (без float).

**Вердикт:** будувати як **CV8d** (кухня+столи+страви), 3–4 дні після CV1; залежність від `cube.rs` годин.

### 2.4 Жести

Події вказівника вже йдуть у Rust (loader 84-88). Потрібен розпізнавач: tap / long-press / drag з інерцією / swipe з порогом швидкості / pinch; скасування при прокрутці; усі цілі хіт-тесту ≥ 44 px (гейт tap-size переписується на сцену — CV7). «Перетягнути замовлення на інший стіл» = `POST /api/staff/sittings/:id/move` з Idempotency-Key, «свайп закрити рахунок» = `pay.js` — маршрути є.

Ризики, які DOM-стек не має: (1) кухня — мокрі пальці та рукавички: кожен жест-дія вимагає підтвердження або «відмотати 5 с»; (2) **WCAG 2.5.1** — дія лише жестом недопустима: кожна має кнопку-альтернативу (тобто жести — прискорювач, не єдиний шлях); (3) `touch-action: none` на canvas вимикає рідну прокрутку — вона вже наша (R-CANVAS). Cheap-Android: `getCoalescedEvents` для гладких траєкторій — Chromium/Firefox, Safari пізніх версій (RECORDED: MDN); без нього drag «ступінчастий» на 60 Hz.

**Вердикт:** будувати як **CV8e** у складі CV0 (розпізнавач — 3–4 дні), використати в CV1 (кухня: свайп «готово», long-press — причина відмови) і CV3 (кошик: свайп видалити).

## 6. Чого НЕ будувати і чому

1. **Моделі у Worker-і** — 10 ms CPU Free (1,4 % запитів уже вбивалися на цій межі); єдиний серверний шлях — Workers AI (бюджет нейронів на акаунт) або ключ власника.
2. **whisper/moonshine на телефоні для обліку** — 3,6 s на 30 s лише енкодер на A78 (1 потік); moonshine — лише англійська; якість whisper-tiny для албанської не виміряна й апріорі низька для tiny; Web Speech API вже є й безкоштовний.
3. **LLM на пристрої** (SmolLM2 118 MB, Qwen 483 MB) — завантаження більше за всю вітрину в 10 000 разів; без застосування, якого не закриває Workers AI/OpenRouter власника.
4. **RMBG-1.4/2.0, NLLB-200, MMS (ASR/TTS)** — ліцензії не для комерції. Беруться лише Apache-2.0/MIT (MODNet, Depth-Anything-small, SlimSAM, silero, whisper, MiniLM, m2m100, opus-mt).
5. **Теплокарти поведінки гостя для власника** і **тепло «по офіціанту»** — перше ламає no-tracking, друге потребує окремого рішення щодо D0.
6. **Мультикурсори** — немає спільного документа.
7. **Haptics на iOS** — немає API без DOM; не обіцяти.
8. **WebGPU як базовий шлях** — Android 12+ лише, бокс не бачить GPU; лише як прогресивне покращення для CV8h.
9. **SDF-текст / власний шейпінг** — ризик кирилиці, ë/ç, IME; Canvas2D-текст лишається (R-CANVAS).
10. **Відмотування каталогу/цін у часі** — KV без історії й так задумано (W-DELTA компактує); ціна на чеку доводиться S5, не слайдером.

## 7. Чого не вдалося виміряти тут

- GPU-кадр (WebGL2/WebGPU) і будь-який WebGPU-інференс — бокс малює порожнечу; потрібен телефон.
- Реальний дешевий Android: усі часи — A78 під proot у Node, не в браузері; множник 2–4× — ESTIMATE.
- Якість whisper-tiny/base для албанської — не виміряна (немає записів; рішення 10-03 вимагає справжніх).
- Батарея — немає інструменту; у CV8j критерій — час кадру, не mAh.
- `getCoalescedEvents` на Safari, haptics-поведінка — лише RECORDED.
- Склейка (CV8f) — ендпоінта S2 ще немає; оцінка на даних E1/E5.
- Розмір candle/tract-wasm для MODNet/Depth — не збирався (бюджет слота); ESTIMATE 1–4 MB.

## 9. Відкриті питання оператору

1. **Машина часу** — лише для персоналу з правом бачити замовлення (контакти гостей у логу), 30 днів гарячого логу. Достатньо, чи потрібен доступ до архівів (тоді це вже не слайдер, а звіт по днях)?
2. **`at` у стокових подіях (CV8c′)** — крихітна зміна формату з законами S7c; дозволяєте запустити до S7c, чи чекати на нього?
3. **Фото-конвеєр (CV8g)** — рахувати в консолі власника на його телефоні (секунди, безкоштовно) чи в DO/Workers AI (там немає моделей глибини/фону — довелося б шукати інший сервіс)? Моя рекомендація — консоль.
4. **Паралакс-картка (CV8h)** — лише під пальцем (батарея) або й за гіроскопом (iOS просить дозвіл окремим діалогом)?
5. **Години в таблиці продажів** — 24 цілих на страву на день (ESTIMATE +4 KB/день) — ок?
6. **Жести** — приймаєте правило «кожна жестова дія має кнопку» (WCAG 2.5.1), тобто жести лише як прискорювач?
7. **Звук на кухні** — дзвінок нового квитка за замовчуванням увімкнено (після першого дотику) чи вимкнено?
8. **Словникові ембединги (CV8i)** — варто, чи тріграмного пошуку (0 MB) достатньо для 165 страв?
9. **Що точно не будуємо** (§6, п. 1–4, 6–7) — підтвердити, щоб наступні пропозиції ззовні про «whisper на телефоні» чи «RMBG» не відкривали лейнів.
